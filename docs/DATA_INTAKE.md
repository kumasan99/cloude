# クロに渡してほしい資料（データ提供ガイド）

> **ReSowグループでは Google Drive 連携で運用しています。**
> 資料は `00.ReSow参謀AI` のDriveに置き、クロが直接読みます。
> 読む場所・読まない場所は [`DRIVE_SOURCES.md`](DRIVE_SOURCES.md) を、
> 現在の不足資料は `config/data_requirements.yaml` とダッシュボードの
> 「クロが待っている資料」を参照してください。
> 以下はローカルフォルダ方式で運用する場合の汎用ガイドです。

CEOがやることは1つだけです。**ファイルを `data/inbox/` の該当フォルダに置く。**
それ以外（整形・集計・解釈）はすべてクロ（COO）側で行います。

---

## 1. 置き場所

```
data/inbox/
├── finance/    財務・資金繰り（試算表、資金繰り表、売上台帳、請求・入金、借入）
├── sales/      売上・案件（パイプライン、受注一覧、見積、失注理由）
├── people/     人・組織（人員名簿、人件費、工数、採用・離職）
├── ops/        業務・現場（議事録、日報、問い合わせ、契約一覧）
└── strategy/   戦略・計画（事業計画、予算、中期計画、競合情報）
```

**ファイル名は自由です。** 会計ソフトから出力したままの名前で構いません。
ただし日付が入っていると、クロが期間を正しく認識できます（例: `試算表_2026-07.xlsx`）。

## 2. 読める形式

| 形式 | 状態 | 備考 |
|---|---|---|
| `.xlsx` | ✅ | Excel。会計ソフトの出力そのままでOK |
| `.csv` / `.tsv` | ✅ | 文字コードはUTF-8推奨（Shift-JISでも大体読めます） |
| `.pdf` | ✅ | テキストが埋め込まれたPDF。**スキャン画像のPDFは読めません** |
| `.txt` / `.md` | ✅ | 議事録・メモ。文字起こしそのままで可 |
| `.json` / `.yaml` | ✅ | ツールからのエクスポート |
| `.docx` / `.pptx` | ❌ | PDFに書き出して置いてください |
| 画像・スキャンPDF | ❌ | 数字だけ手入力のメモにするか、テキスト化してください |

読めなかったファイルは、ダッシュボードに「読み取れなかった」として表示されます。黙って無視はしません。

---

## 3. 優先度A — これが無いと経営判断ができません

まずこの6つ。**ここだけ揃えば、ダッシュボードは実データで動き始めます。**

### A-1. 月次試算表（直近12ヶ月）→ `data/inbox/finance/`
- **なぜ**: 売上・粗利・固定費・営業利益の実額と推移。これが無いと損益の話が一切できません。
- **形式**: Excel / CSV
- **取り出し方**: freee・マネーフォワード・弥生 → レポート → 試算表 → 期間を12ヶ月にしてエクスポート
- **頻度**: 毎月（月次締め後）

### A-2. 資金繰り表 または 預金残高推移 → `data/inbox/finance/`
- **なぜ**: 会社が止まるのは赤字のときではなく現金が尽きたときです。「あと何ヶ月もつか」の算出に必須。
- **形式**: Excel / CSV。無ければ**各口座の月末残高を並べたメモでも構いません**
- **取り出し方**: 会計ソフトの資金繰りレポート、またはネットバンキングの残高推移CSV
- **頻度**: 毎月

### A-3. 売上明細（顧客別・月別）→ `data/inbox/finance/`
- **なぜ**: 売上の中身が分からないと「どの顧客に依存しているか」が判断できません。顧客集中リスクの検知に使います。
- **形式**: CSV / Excel（**顧客名・年月・金額の3列があれば十分**）
- **取り出し方**: 会計ソフトの得意先元帳、請求管理ツールの請求一覧
- **頻度**: 毎月

### A-4. 案件パイプライン（商談中の一覧）→ `data/inbox/sales/`
- **なぜ**: 来月以降の売上見通し。これが無いと、採用や投資の判断ができません。
- **形式**: CSV / Excel（案件名・顧客・金額・確度・受注予定月）
- **取り出し方**: CRM・営業管理シートをCSVで書き出し。**無ければ手書きの一覧でも構いません**
- **頻度**: 毎週

### A-5. 人員名簿と人件費 → `data/inbox/people/`
- **なぜ**: 人件費は中小企業の最大の固定費。何人で回していていくらかかっているかが全ての前提です。
- **形式**: Excel / CSV（**氏名は伏せて「役割・雇用形態・月額人件費」でも可**）
- **取り出し方**: 給与計算ソフトの支給一覧
- **頻度**: 変動があったとき

### A-6. 事業計画 または 年度予算 → `data/inbox/strategy/`
- **なぜ**: 「予定に対してどうか」を判断する基準。これが無いと実績を良い/悪いと評価できません。
- **形式**: Excel / PDF
- **未作成の場合**: 「未作成」と伝えてください。クロが作成を improvements に上げます。
- **頻度**: 年1回

---

## 4. 優先度B — 判断の精度が大きく上がります

| 資料 | 置き場所 | 何が分かるか |
|---|---|---|
| 経費明細（勘定科目別） | `finance/` | どこに何がかかっているか。コスト削減の打ち手の根拠 |
| 借入金一覧・返済予定表 | `finance/` | 毎月の固定的な流出。追加投資の余力判断に直結 |
| プロジェクト別採算・工数 | `people/` | 「忙しいのに儲からない」の原因特定。赤字案件の発見 |
| 受注・失注の記録（理由つき） | `sales/` | 失注理由が価格か納期か体制かで打ち手が変わる |
| 経営会議・定例の議事録 | `ops/` | 数字に出る前の兆候（人の不満、止まっている案件） |
| 採用・離職の状況 | `people/` | 数ヶ月遅れで売上に効く。早期に判断が要る領域 |

## 5. 優先度C — 余力があれば

契約一覧（更新期日つき）／ 組織図・役割分担表 ／ 競合・市場の情報

---

## 6. 秘密情報の扱い

- `data/inbox/` の中身と生成されたレポートは **`.gitignore` 済み**で、Gitにコミットされません。
- 個人名・口座番号・マイナンバーなど、渡す必要のない情報は消してから置いてください。
  人員名簿は「役割 + 金額」だけで十分に機能します。
- ファイルの内容はレポート生成時に Claude API に送信されます。社外に出せない資料は置かないでください。

---

## 7. 最初の一歩

全部を揃えようとしないでください。**まず `finance/` に試算表を1本置いて、ダッシュボードで「レポートを更新」を押す。**
それだけで、クロが「次に何が必要か」を具体的に返してきます。以降はその指示に従って足していけば十分です。
