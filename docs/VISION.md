# ReSow経営ダッシュボード構想

作成: 2026-08-22 / クロ（COO）→ 熊野社長
閲覧用ページ: claude.ai の Artifact「ReSow経営ダッシュボード構想」として公開済み

## この仕組みの約束

社内に散らばる情報をクロが読み、社長が**読むだけで意思決定できる**状態に整えて毎週届ける。
社長がやることは2つだけ。

1. 資料を置く（またはクロが取りに行く）
2. 判断カードに 承認 / 却下 / 保留 を返す

集める・突き合わせる・解釈する・試算する・催促する——それ以外はクロの仕事。

## 全体の流れ

```
データ源                      クロ（COO）              出口
─────────────                ────────────            ─────────────
マネーフォワード（月次PL・仕訳） ┐
Google Drive（資金繰り・売上）  ├→ 読解・突合・試算 →  ダッシュボード6ブロック
議事録3系統（役員/取締役/コア）  │   提案・追跡          （サマリー/判断/KPI/改善/
Plaud録音（ルール内）          ┘                        リスク/不足資料）
                                                          ↓
                              ←── 判断の理由が翌週の ── 決裁ログ
                                   報告精度を上げる
```

実体は3層: `config/`（会社の前提・KPI定義・資料台帳=判断基準）、`coo/`（取込・分析・保存）、`/dashboard`（画面）。
判断基準がコードから分離されているため、社長の関心が変われば設定の書き換えだけで報告の切り口が変わる。

## 設計原則

1. **出典主義** — 数字には出典ファイル名。補完値は「推定」と明記
2. **判断の純度** — 判断カードには社長にしか決められないことだけ
3. **言い切る** — 選択肢と推奨を必ずセットで
4. **不足は隠さない** — 何が無いせいで何が決められないかまで書く
5. **機微の線引き** — 読まない場所はフォルダIDで固定。録音は経営系のみ

## ロードマップ

順番に意味がある: **手で回して型を作る → 型を自動にする → 水準を上げる**。

### Phase 1: 週次運用の確立（いま〜9月中旬）
- 週次レポートの定着（社長は判断を返すだけ）
- 資金繰り表の下書き生成（MFの入出金・仕訳から。野原さんは確認役に）
- 返還リスク試算の支援（処遇改善加算・定員超過。大阪市の依頼到着前に）
- 8/28経営会議・9/11中計発表会の裏方

### Phase 2: 自動化と拡張（9月〜11月）
- 毎週月曜の自動生成（月曜朝にレポートが待っている状態）
- アラート（現金残高・退職数・事業所売上の閾値監視）
- グループ他法人の取り込み（パートナーズ・COCO・HD）
- 週次KPI進捗_v7・利用者数/稼働率との統合
- 経費統制（8月開始の事前承認制度）の効果測定

### Phase 3: IPO水準の経営管理（11月〜）
- 月次決算5営業日（記帳2ヶ月遅れの解消）
- グループ連結ビュー（単純合算→内部取引消去。HD請求問題の整理が前提）
- 予実管理（中期経営計画を基準線に）
- 金融機関向けパッケージのワンクリック出力

## 前提とリスク

- MF接続はベータ提供。取得値は当面、資金繰り表・決算統合と突合してから使う
- 記帳は約2ヶ月遅れ。直近の損益は「6月まで確定・以降は推定」と明示
- 5社合算は単純合算（連結消去なし）。合算値には常に注記
- 認証はすべて社長のアカウント経由。クロはID・パスワードを保持しない
